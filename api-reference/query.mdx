title: "POST /query — AI-Synthesized Answers with Citations"

---

Send a natural-language question to `/query` and Almendra retrieves the most relevant chunks from your knowledge base, synthesizes them into a coherent answer using an LLM of your choice, and returns a confidence score alongside direct source citations. Use this endpoint when you want a ready-to-display answer rather than raw document chunks.

## Endpoint

```
POST https://api.almendra.ai/api/v1/query
```

## Request Body

<ParamField body="question" type="string" required>
  The natural-language question to ask. Write your question exactly as you would phrase it to a human expert — the more specific the question, the more targeted the answer.
</ParamField>

<ParamField body="source_ids" type="string[]">
  Limit the query to specific source IDs. Pass an array of source ID strings (e.g., `["src_abc123", "src_def456"]`) to restrict retrieval to those sources only. Defaults to all sources the API key can access.
</ParamField>

<ParamField body="top_k" type="integer" default={5}>
  Number of source chunks to retrieve before synthesis. A higher value gives the model more context but may introduce noise. Must be between `1` and `20`.
</ParamField>

<ParamField body="model" type="string" default="auto">
  LLM to use for answer synthesis. Supported values:

  | Value | Description |
  |---|---|
  | `auto` | Uses the workspace default model (recommended) |
  | `claude-3-5-sonnet` | Anthropic Claude 3.5 Sonnet |
  | `gpt-4o` | OpenAI GPT-4o |
  | `gemini-1.5-pro` | Google Gemini 1.5 Pro |
</ParamField>

## Example Request

<CodeGroup>

```bash cURL
curl -X POST https://api.almendra.ai/api/v1/query \
  -H "Authorization: Bearer $ALMENDRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "What is our SLA for enterprise customers?",
    "top_k": 5
  }'
```

```python Python
import os
import requests

response = requests.post(
    "https://api.almendra.ai/api/v1/query",
    headers={
        "Authorization": f"Bearer {os.environ['ALMENDRA_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "question": "What is our SLA for enterprise customers?",
        "top_k": 5,
    },
)
print(response.json())
```

```javascript Node.js
const response = await fetch("https://api.almendra.ai/api/v1/query", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.ALMENDRA_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    question: "What is our SLA for enterprise customers?",
    top_k: 5,
  }),
});

const data = await response.json();
console.log(data);
```

</CodeGroup>

## Response Fields

<ResponseField name="answer" type="string">
  The synthesized answer to your question, generated by the LLM using the retrieved source chunks as context.
</ResponseField>

<ResponseField name="confidence" type="float">
  A score from `0.0` to `1.0` indicating how strongly the retrieved evidence supports the answer. Scores above `0.8` indicate high-confidence answers backed by clear, consistent source material.
</ResponseField>

<ResponseField name="sources" type="object[]">
  An array of source citation objects used to generate the answer.

  <Expandable title="Source object fields">
    <ResponseField name="id" type="string">
      Unique chunk identifier. Use this to retrieve or dereference the specific chunk.
    </ResponseField>

    <ResponseField name="title" type="string">
      Human-readable title of the source document the chunk belongs to.
    </ResponseField>

    <ResponseField name="source" type="string">
      The connector name that provided this chunk (e.g., `notion`, `confluence`, `github`, `api`).
    </ResponseField>

    <ResponseField name="score" type="float">
      Relevance score for this individual chunk relative to the question, from `0.0` to `1.0`.
    </ResponseField>

    <ResponseField name="url" type="string">
      Direct URL to the source document, if available.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="escalated" type="boolean">
  `true` if the question could not be answered with sufficient confidence and should be routed to a human expert. When `escalated` is `true`, treat the `answer` field as a best-effort response and surface it with appropriate caveats.
</ResponseField>

<ResponseField name="model_used" type="string">
  The identifier of the LLM that generated the answer. Useful for auditing and debugging when `model` is set to `auto`.
</ResponseField>

## Example Response

```json
{
  "answer": "Enterprise customers are guaranteed 99.9% uptime under our SLA, with a maximum response time of 1 business hour for P1 incidents.",
  "confidence": 0.94,
  "sources": [
    {
      "id": "chunk_abc123",
      "title": "Enterprise SLA — Legal Docs",
      "source": "notion",
      "score": 0.95,
      "url": "https://notion.so/enterprise-sla"
    }
  ],
  "escalated": false,
  "model_used": "claude-3-5-sonnet"
}
```

## Error Responses

<Accordion title="400 Bad Request">
  Returned when the request body is malformed or a required parameter is missing.

  ```json
  {
    "error": {
      "code": "bad_request",
      "message": "The 'question' field is required and must be a non-empty string."
    }
  }
  ```

  Check that `question` is present and that `top_k` is an integer between `1` and `20`.
</Accordion>

<Accordion title="401 Unauthorized">
  Returned when the `Authorization` header is missing, malformed, or contains an invalid API key.

  ```json
  {
    "error": {
      "code": "unauthorized",
      "message": "Invalid or missing API key. Provide a valid Bearer token in the Authorization header."
    }
  }
  ```

  Verify your API key in the Almendra dashboard under **Settings → API Keys**.
</Accordion>

<Accordion title="429 Too Many Requests">
  Returned when you exceed the rate limit for your plan. The response includes a `Retry-After` header indicating how many seconds to wait before retrying.

  ```json
  {
    "error": {
      "code": "rate_limit_exceeded",
      "message": "You have exceeded the request rate limit. Please retry after 30 seconds."
    }
  }
  ```

  Implement exponential backoff in your integration to handle bursts gracefully.
</Accordion>
