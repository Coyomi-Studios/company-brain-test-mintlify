Use `/ingest` to push content directly into your Almendra knowledge base without configuring a native connector. Almendra accepts either raw text or a URL, splits the content into overlapping chunks, embeds each chunk into the vector store, and makes it immediately searchable. Ingested content behaves identically to connector-sourced content for all downstream `/query` and `/search` requests.

## Endpoint

```
POST https://api.almendra.ai/api/v1/ingest
```

## When to Use `/ingest`

Use `/ingest` for content that is not covered by a native connector. Common use cases include:

- **Form submissions** — Capture support tickets, feedback, or intake forms as they arrive.
- **Scraped or processed documents** — Push pre-processed text from PDFs, Word documents, or HTML pages your pipeline has already parsed.
- **System-generated content** — Index runbooks, release notes, or configuration summaries produced by your own automation.
- **Public web pages** — Provide a URL and Almendra will fetch, parse, and index the page automatically.

## Request Body

<ParamField body="content" type="string" required>
  The text content to ingest. Accepts plain text or Markdown. Required unless you provide `url`. The content you supply is chunked and embedded as-is, so clean and well-structured input produces better retrieval results.

  <Note>
    Provide either `content` or `url` — not both. If both are supplied, the request returns a `400` error.
  </Note>
</ParamField>

<ParamField body="url" type="string">
  A publicly accessible URL. When you provide a URL instead of `content`, Almendra fetches the page, strips navigation and boilerplate, and indexes the main body text. JavaScript-rendered pages are not supported — the URL must return parseable HTML or plain text.
</ParamField>

<ParamField body="metadata" type="object">
  Key-value metadata attached to every chunk produced from this ingest. Metadata is stored alongside each chunk and returned in `/search` and `/query` responses, making it easy to filter or attribute results.

  <Expandable title="Metadata fields">
    <ParamField body="metadata.title" type="string">
      Human-readable title for the document. Displayed in source citations returned by `/query`.
    </ParamField>

    <ParamField body="metadata.source" type="string">
      A short label identifying the origin of the content (e.g., `"handbook"`, `"support-form"`, `"public-docs"`). Used for filtering with `source_ids` in `/query` and `/search`.
    </ParamField>

    <ParamField body="metadata.author" type="string">
      The name or identifier of the person or system that authored the content.
    </ParamField>

    <ParamField body="metadata.tags" type="string[]">
      An array of searchable tag strings to associate with all chunks from this ingest (e.g., `["policy", "billing", "legal"]`).
    </ParamField>
  </Expandable>
</ParamField>

## Example Requests

<CodeGroup>

```bash Raw text (cURL)
curl -X POST https://api.almendra.ai/api/v1/ingest \
  -H "Authorization: Bearer $ALMENDRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "Our enterprise refund policy allows returns within 30 days of purchase. Renewals are non-refundable except where required by law.",
    "metadata": {
      "title": "Refund Policy",
      "source": "handbook",
      "author": "ops-team",
      "tags": ["policy", "billing"]
    }
  }'
```

```bash URL ingest (cURL)
curl -X POST https://api.almendra.ai/api/v1/ingest \
  -H "Authorization: Bearer $ALMENDRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://docs.yourcompany.com/api/overview",
    "metadata": {
      "source": "public-docs"
    }
  }'
```

```python Python
import requests

        "content": "Our enterprise refund policy allows returns within 30 days of purchase. Renewals are non-refundable except where required by law.",

            "title": "Refund Policy",
            "source": "handbook",
            "author": "ops-team",

        },
    },
)
print(response.json())
```

## Response Fields

<ResponseField name="id" type="string">
  Unique identifier for this ingest job. Use this ID to poll the status of asynchronous ingests via `GET /api/v1/ingest/{id}`.
</ResponseField>

<ResponseField name="status" type="string">
  Processing status of the ingest job. One of two values:

  - `indexed` — Content was small enough to process synchronously. Chunks are immediately available for search and query.
  - `processing` — Content is being processed asynchronously (typical for large documents or URL ingests). Poll `GET /api/v1/ingest/{id}` for completion.
</ResponseField>

<ResponseField name="chunks" type="integer">
  The number of chunks created from the ingested content. Only present when `status` is `indexed`. Use this to verify that your content was split as expected.
</ResponseField>

## Example Response

```json
{
  "id": "ingest_abc123",
  "status": "indexed",
  "chunks": 2
}
```

<Tip>
  For large batches, poll `GET /api/v1/ingest/{id}` to check when processing is complete.
</Tip>

## Error Responses

<Accordion title="400 Bad Request">
  Returned when neither `content` nor `url` is provided, both are provided at the same time, or a field value is invalid.

  ```json
  {
    "error": "bad_request",
    "message": "Provide either 'content' or 'url', not both."
  }
  ```
</Accordion>

<Accordion title="401 Unauthorized">
  Returned when the `Authorization` header is missing or contains an invalid API key.

  ```json
  {
    "error": "unauthorized",
    "message": "Invalid or missing API key. Provide a valid Bearer token in the Authorization header."
  }
  ```
</Accordion>

<Accordion title="422 Unprocessable Content">
  Returned when the provided `url` could not be fetched or parsed. Check that the URL is publicly accessible and returns parseable HTML or plain text.

  ```json
  {
    "error": "unprocessable_content",
    "message": "Failed to fetch the provided URL. Ensure the page is publicly accessible and returns parseable HTML."
  }
  ```
</Accordion>

<Accordion title="429 Too Many Requests">
  Returned when you exceed the rate limit for your plan. Respect the `Retry-After` header in the response.

  ```json
  {
    "error": "rate_limit_exceeded",
    "message": "You have exceeded the request rate limit. Please retry after 30 seconds.",
    "retry_after": 30
  }
  ```
</Accordion>
