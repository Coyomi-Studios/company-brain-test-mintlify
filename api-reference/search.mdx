Use `/search` to run semantic vector search across your knowledge base and receive a ranked list of the most relevant document chunks. Unlike `/query`, this endpoint does not invoke an LLM — it returns the raw chunks directly, giving you full control over how you present or process the results downstream.

## Endpoint

```
POST https://api.almendra.ai/api/v1/search
```

## Request Body

<ParamField body="query" type="string" required>
  The search text to match against your knowledge base. Accepts natural language phrases, keywords, or a mix of both. Almendra embeds your query and performs cosine similarity search across all indexed chunks.
</ParamField>

<ParamField body="top_k" type="integer" default={5}>
  Number of results to return. Results are ordered by relevance score, highest first. Must be between `1` and `20`.
</ParamField>

<ParamField body="source_ids" type="string[]">
  Limit the search to specific source IDs. Pass an array of source ID strings to restrict which sources are searched. Omit this field to search across all sources the API key can access.
</ParamField>

<ParamField body="min_score" type="float">
  Minimum relevance score threshold, from `0.0` to `1.0`. Chunks with a score below this value are excluded from the response even if they would otherwise fall within `top_k`. Useful for filtering out low-quality matches. If omitted, no minimum threshold is applied.
</ParamField>

## Example Request

<CodeGroup>

```bash cURL
curl -X POST https://api.almendra.ai/api/v1/search \
  -H "Authorization: Bearer $ALMENDRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "SAML SSO configuration steps",
    "top_k": 3,
    "min_score": 0.7
  }'
```

```python Python
import requests

response = requests.post(
    "https://api.almendra.ai/api/v1/search",
    headers={
        "Authorization": f"Bearer {ALMENDRA_API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "query": "SAML SSO configuration steps",
        "top_k": 3,
        "min_score": 0.7,
    },
)
print(response.json())
```

```javascript Node.js
const response = await fetch("https://api.almendra.ai/api/v1/search", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.ALMENDRA_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    query: "SAML SSO configuration steps",
    top_k: 3,
    min_score: 0.7,
  }),
});

const data = await response.json();
console.log(data);
```

</CodeGroup>

## Response Fields

<ResponseField name="results" type="object[]">
  An array of matching document chunks, ordered by relevance score from highest to lowest.

  <Expandable title="Result object fields">
    <ResponseField name="id" type="string">
      Unique identifier for this chunk. Use this ID when referencing a specific chunk in other API calls.
    </ResponseField>

    <ResponseField name="text" type="string">
      The full text content of the retrieved chunk, exactly as it was indexed. This is the raw passage you can display, highlight, or pass to your own LLM.
    </ResponseField>

    <ResponseField name="score" type="float">
      Relevance score from `0.0` to `1.0` indicating how closely this chunk matches your query. Scores above `0.85` generally indicate a strong semantic match.
    </ResponseField>

    <ResponseField name="source" type="string">
      The connector name that provided this chunk (e.g., `confluence`, `notion`, `github`, `url`, `api`).
    </ResponseField>

    <ResponseField name="title" type="string">
      Human-readable title of the source document this chunk belongs to.
    </ResponseField>

    <ResponseField name="url" type="string">
      Direct URL to the source document, if available.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of chunks that matched the query above the `min_score` threshold, before `top_k` truncation. Use this to determine whether additional relevant content exists beyond what was returned.
</ResponseField>

## Example Response

```json
{
  "results": [
    {
      "id": "chunk_xyz789",
      "text": "To configure SAML SSO, navigate to Settings → Security → SSO. Upload your IdP metadata XML file and click Verify Connection.",
      "score": 0.93,
      "source": "confluence",
      "title": "Auth Architecture — Engineering Wiki",
      "url": "https://confluence.yourcompany.com/auth-architecture"
    }
  ],
  "total": 1
}
```

<Note>
  Search returns raw chunks without LLM synthesis. Use `POST /query` if you want a synthesized answer with citations.
</Note>

## Error Responses

<Accordion title="400 Bad Request">
  Returned when the request body is malformed or a required parameter is missing.

  ```json
  {
    "error": "bad_request",
    "message": "The 'query' field is required and must be a non-empty string."
  }
  ```

  Ensure `query` is a non-empty string and that `top_k` is between `1` and `20` if provided.
</Accordion>

<Accordion title="401 Unauthorized">
  Returned when the `Authorization` header is missing, malformed, or contains an invalid API key.

  ```json
  {
    "error": "unauthorized",
    "message": "Invalid or missing API key. Provide a valid Bearer token in the Authorization header."
  }
  ```
</Accordion>

<Accordion title="429 Too Many Requests">
  Returned when you exceed the rate limit for your plan. Respect the `Retry-After` header in the response.

  ```json
  {
    "error": "rate_limit_exceeded",
    "message": "You have exceeded the request rate limit. Please retry after 30 seconds.",
    "retry_after": 30
  }
  ```
</Accordion>
