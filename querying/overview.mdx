Almendra gives you two distinct ways to extract knowledge from your connected sources. The first is **AI Q&A**, which takes a natural-language question and returns a single synthesized answer drawn from across your knowledge base, complete with source citations and a confidence score. The second is **Semantic Search**, which skips synthesis entirely and returns a ranked list of raw document chunks that match your query. Both modes run through the same permission-aware index, so every user — whether human or an API-calling agent — only ever sees content they are authorized to access.

## Choosing a Query Mode

Understanding when to reach for each mode will help you and your team get the most out of Almendra.

<CardGroup cols={2}>
  <Card title="AI Q&A" icon="circle-question">
    Ask a question in plain language and receive a single, synthesized answer. Best for getting a direct, trustworthy response without needing to read through multiple documents. Almendra cites every source it used and attaches a confidence score so you know how well the answer is grounded.
  </Card>
  <Card title="Semantic Search" icon="magnifying-glass">
    Retrieve ranked document chunks without synthesis. Best for finding relevant source material directly — for example, to pass as context to your own LLM pipeline, to build a custom search UI, or to audit which documents cover a topic.
  </Card>
</CardGroup>

## How the Permission-Aware Index Works

Every query — regardless of mode — is evaluated against your workspace's access controls before any content is returned. When a user submits a question or search query, Almendra checks which connected sources that user is permitted to read and limits the index search to those sources. This means:

- A support engineer who can access Confluence but not a private legal Notion space will never see legal documents in their answers or search results.
- API queries made with a service account token inherit the permissions assigned to that service account.
- Admins with full access see answers synthesized from the entire knowledge base.

No additional configuration is required to enforce this — permissions are inherited from the source integrations you set up during connection.
